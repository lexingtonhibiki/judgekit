# NanoJev 中文低准根因分析（含级联实验与提升路径）

> 2026-09-20 ｜ 数据：judge-econ 130 条逐条记录（零成本复算，脚本 docs/analyze_nanojev_zh.py）

## 一句话根因

**不是"能力弱"，是三重机制叠加：二元任务上预测坍缩到默认类（29/30 全说"正面"）、
置信度与正确性脱钩（0.8+ 桶准确率 60.3% 反而低于 0.6–0.8 桶的 66.7%）、
因此校准门控也救不了它（τ=0.95 要升级 98.5% 才回到规则基线的 91.5%）。**

## 证据

### 1) OOD 下决策头退化为"先验回放"（坍缩实锤）

| dataset | gold 分布 | 预测最多类 |
|---|---|---|
| sentiment_zh | 15/15 均衡 | **正面 29/30** |
| spam_zh | 15/15 均衡 | **正常 29/30** |
| urgency_zh | 15/15 均衡 | **非紧急 27/30** |
| intent_zh | 5 类均衡 | 物流查询 11/40（相对健康） |

模型没见过中文情感/垃圾/紧急度分布 → 决策头输出退化到训练分布先验 →
53.3%/46.7% 的"掷硬币"其实是"单边猜测"的必然结果。intent 略好（80%）是因为
游戏训练里也有"多类别局部判断"结构，与路由任务形态更近。

### 2) 置信度-正确性脱钩（对比 Jev 的发现正好反转）

| conf 桶 | n | acc |
|---|---|---|
| [0,0.4) | 2 | 50.0% |
| [0.4,0.5) | 13 | 61.5% |
| [0.5,0.6) | 13 | 53.8% |
| [0.6,0.8) | 39 | 66.7% |
| [0.8,1.0) | 63 | **60.3%** |

Jev 在域内是"校准概率"（低置信=真该怀疑）；NanoJev 在 OOD 上是**自信地乱猜**——
校准性本身就是域内训练的产物，不是架构自带的。

### 3) 置信度门控级联救不了 OOD 模型

τ 扫描（NanoJev 高置信自己答 / 低置信交规则基线）：τ=0.85 → 83.1%（升级 63.8%）；
要到 91.5% 必须升级 98.5%——级联的价值完全来自"置信度可信任"，**门控的失效比准确率低
更能说明"分布对齐是判官的前提条件"**。这对 judgekit 是重要论点：门控模式需要域内校准。

### 4) 边界样本互补性

Jev 错的 3 条里 NanoJev 对了 2 条（i030 保修政策咨询、p027 负评）——0.6B 与 Jev 的错误
不完全重叠，微调后存在 ensemble 空间；但 p004（软广）它以 0.90 置信度自信地错。

## 提升路径（按成本排序，全部可验证）

1. **域内 LoRA 微调（根治，¥0 算力）**：0.6B + 中文分类数据（决策头继续训，混 1:1 游戏数据防遗忘）。
   数据用 GLM-5.3-flash（订阅内、并发 2）自一致性采样产软标签，1–2 万条合成 + judge-econ 130 条做测试集。
   预期：情感/垃圾 90%+（二分类对 0.6B 足够），总体 90%+。这是最高性价比动作。
2. **底座换 Qwen3.5**：语言先验强一个量级。你本地已有：
   - `D:/Models/Qwen/Qwen3.5-4B`（HF 全精度）——训练底座首选
   - **`D:/Models/Wukong/wukomg2.2-lite`（实为 Qwen3.5-9B 的 GGUF 量化，Q4_K_M≈5.5GB 可进 8GB 显存）**——零样本 judge 立即可测（需装 llama.cpp）
   - `D:/Models/Spark/Spark-X2.5-4B`（讯飞星火 2.5 架构 4.1B GGUF Q8_0）——底座候选，需确认 llama.cpp 对 spark2_5 架构的支持
3. **软标签质量**：模拟器真值没了，替代品是 LLM 自一致性投票（k=3 温度采样取分布）——
   校准能力从标签分布继承，这正是 NanoJev 管线里"observed event q"的中文域替身。
4. **评估协议照抄 judge-econ**：训练后跑 130 条 + 3 轮确定性 + 门控捕获率，防止"训完又是自信乱猜"。
