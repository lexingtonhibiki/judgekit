# 自训 Jev 类判官模型：成本评估（2026-09-20）

> 视角：个人开发者，本机 RTX 2070 8GB + D:\Models 已有 Qwen3.5-4B/9B，参照 NanoJev 公开管线。

## 结论先行

| 路线 | 算力成本 | 数据成本 | 结果预期 |
|---|---|---|---|
| **复刻 NanoJev（0.6B，游戏域）** | ¥0（本机 LoRA）~ ¥30（租 4090 全参） | ≈0（模拟器自动产概率标签） | NanoJev 同级：导航/几何判断 95%，域外弱 |
| **业务域 0.6B–4B 判官**（推荐） | ¥30–300（LoRA/QLoRA） | **真正的成本所在**：合成 ¥0–500 + 人工核验 ¥1000+ | 中文客服分类有望 96–98%+，本地部署零边际 |
| **4B+ 底座冲"更好的 Jev"** | QLoRA 本机可训；全参建议租 A10/4090 ¥100–500 | 同上，且需更大规模 | 与 Jev API 比拼通用域大概率仍弱，但本地部署+数据主权是差异化 |

算力从来不是门槛——**0.6B 全参 100 步 BF16 在 4090 上只要几块钱电费/租金；数据与评估工程才是成本主体**（NanoJev 的大部分价值在管线纪律：契约审计、对照实验、轨迹回放校验）。

## 本机可行性（RTX 2070 8GB）

- **推理**：0.6B BF16 ≈ 1.2GB 显存——无压力，已实测路径（serve_decisions.py bf16）
- **训练**：0.6B 全参 AdamW 需 ~8.4GB（权重+梯度+fp32 动量），8GB 卡放不下 →
  用 **LoRA/QLoRA**（显存 2–4GB，本机可训）或租 4090（¥1.5–2.5/h，全参几小时）
- 4B 底座：本机 QLoRA 勉强可行（4-bit 量化 + LoRA + 小 batch + 梯度累积）；认真训练建议租卡

## D:\Models 底座盘点与建议

| 本地模型 | 适合作判官底座？ |
|---|---|
| **Qwen3.5-4B** | ★ 首选：语言先验远强于 Qwen3-0.6B，中文能力内置，LoRA 加决策头即可 |
| Qwen3.5-9B | 精度上限更高，但 8GB 卡只能 QLoRA+offload，训练慢；推理可用 |
| Qwen3-Embedding-0.6B | 不是生成底座，不适用 |
| Spark-X2.5-4B / LTX-Video / Wukong | 语音/视频/图像域，不适用 |

 NanoJev 用 Qwen3-0.6B 的原因之一就是小（训练快、实验迭代密）；**冲质量应该用 4B**。

## "更好的 Jev"的配方（开源可复刻路线）

1. **底座**：Qwen3.5-4B（或 Qwen3-1.7B 平衡档）
2. **头**：照抄 NanoJev 决策头设计（choice=标量头+set attention / boolean=sigmoid / score=有序级），零解码读概率
3. **数据三混合**：
   - 模拟器数据（保概率校准，免费，参照 NanoJev 的 CE/Brier + proper-reward 目标）
   - **中文业务合成数据**（用免费链 LLM 生成客服工单/评论 + 自一致性投票产软标签——便宜但校准要验证）
   - 少量人工核验集（judge-econ 130 条可直接当种子测试集）
4. **损失**：CE/Brier 直接损失为主（NanoJev 自己的结论：采样式 RLCD 并未证明优于直接控制），paired proper-reward 作为研究方向
5. **评估**：judge-econ 基准 + 3 轮零漂移确定性检验 + 置信度门控捕获率（现成协议）

## 与 Jev API 的定位关系

Jev 是专用训练的大规模判官（推测 MoE 蒸馏），通用域精度/概率质量大概率仍领先开源复刻。
开源路线的差异化不在精度追平，而在：**本地部署（数据不出域）+ 零边际成本 + 无配额无限流 +
可微调到私有域**。对客服派单/内容审核这类高频内网场景，这些往往比最后 1–2 个点的精度更重要。
